# CENTURY — mockup brief (read fully before writing anything)

You are writing throwaway HTML/CSS UI mockups for **CENTURY**, a Unity prototype: a historically authentic Roman survival / band-management game set after the Teutoburg Forest disaster (AD 9). The player is **Centurion Marcus Cornelius** of the lost Nineteenth Legion, leading the survivors of his Century (~41 men now) home across hostile Germania. Three layers of play: **Overmap** (click-to-move map, points of interest, roaming warbands, line-of-sight fog), **Battle** (real-time, cursor-driven; the Centurion is directly controlled and gives orders to contubernia = 8-man squads), **Camp** (a management screen: rest, officer posts, stations, crafting, orders). The audience for these mockups is the game's designer, who opens them in a browser to judge layout and look before building them in Unity UI Toolkit.

## Visual identity (non-negotiable)
"Parchment & Wax" — a campaign ledger. Aged-parchment panels (soft gradient + inner sheen + warm drop shadow), 1px umber/bronze edges, iron-gall ink text, umber small-caps headings with letter-spacing, wax-seal red for danger/emphasis, serif type (Palatino stack). The world behind the HUD reads as a hand-drawn campaign map: mottled parchment ground, ink-hatched forests, slate-ink rivers, charcoal × marks for enemies, red-crested square marks for our men, a compass rose. Nothing pure white or pure black. **NO** photographic textures, **NO** ornate/fantasy frames, **NO** rounded corners beyond 2–4px (keycaps, tier discs and wax seals excepted), **NO** emoji, **NO** unicode dingbats beyond `◆ — · › × + !`. Colours ONLY via the CSS variables in `common.css`. Legacy variable names are inverted but kept: `--ink*` are now the parchment SURFACES and `--parchment*` are now the INK text colours. Semantic colours: `--blood` wax red danger/health/enemy, `--olive` good/morale, `--brass` stamina/bronze accents/selected, `--amber` wounded/low stock, `--umber` headings, `--gold-bright` emphasis bronze (darker = stronger on parchment), `--parchment-dim` secondary ink, `--parchment-faint` faded/disabled ink. New helpers: `--parch-hi/--parch-lo` (panel gradient stops), `--edge`, `--wax-hi/--wax-lo` (seal gradient), `--paper-glow`, `--ink-wash`. Reference: `../HUD-Styles/01-parchment-wax.html` is the canonical look. Icons come from the inline SVG sprite (`icons.svg`) via `<svg class="ico"><use href="#i-helmet"/></svg>` — use only symbol ids that exist there (open the file and check). Sizes: `.ico--sm .ico--lg .ico--xl`; tints: `.ico--gold .ico--dim` or any `text-*` colour class on the svg.

## Copy rules
1. **Entity descriptions state MECHANICS, never flavour** — an office card says what the holder does to the sim ("Orders reach squads sooner. A vacancy slows every order."), a doctrine says its effect, an item says what it's for, a station says what it unlocks. Narrative text (subtitles, event prose, narration) may be flavourful.
2. **The game hides percentages from the player.** Morale is a ladder word: Broken / Breaking / Wavering / Confident / Fearless. Veterancy: "Tiro (Recruit) / Miles (Trained) / Veteranus (Veteran) / Evocatus (Elite)". Equipment: Serviceable / Worn / Failing. Pace: Camped / Slow / Normal / Quick. Bars are fine; numbers beside bars are not (counts of men, days of food, coin ARE shown as numbers).
3. Labels are UPPERCASE via CSS `text-transform` on the class (eyebrow/heading/pill/etc. already do it). Body prose is sentence case.
4. Latin sparingly and correctly: contubernium/contubernia, decanus/decani, optio, tesserarius, signifer, medicus, speculator, signum, pilum/pila, gladius, scutum, framea/frameae, testudo, vexillum.
5. Keys are shown with `<span class="keycap">W</span>` (never the Kenney icon pack — it's not available here).

## Fragment format
Each mockup is ONE fragment file at `pages/NN-name.html` (paths below):
```
<!-- title: Battle Summary -->
<!-- desc: One sentence for the gallery card. -->
<!-- world: battle -->        one of: overmap | battle | camp | title | none  (paints a stand-in backdrop behind the HUD)
<style> /* page-specific CSS only; common.css is already inlined by the builder */ </style>
...markup...
```
The markup is placed inside `<div id="stage">` — a fixed **1920×1080** canvas — inside `<div class="hud-root">` (`position:absolute; inset:0`). Absolute positioning within the stage is fine and encouraged for HUD elements; modals should use `.modal` (full-stage dim) + `.modal__sheet`. The builder (`build.py`) wraps the fragment with the doctype, inlines `common.css` and the icon sprite, and adds a tiny script that: scales the stage to the window; toggles `body.notes` with the **N** key; and wires simple tabs — any element with `data-tabs` whose children carry `data-tab="x"` switches which `[data-page="x"]` element is visible (give non-default pages the `hidden` attribute; the active tab carries `pill--active`, `nav-item--active` or `tab--active` depending on its class).

Do NOT add `<html>/<head>/<body>`. Do NOT load external resources (no CDNs, no images) — draw everything with CSS and inline SVG. Do NOT run the build and do NOT open a browser — just write the fragment(s). **Read `common.css` and `icons.svg` first** and reuse their classes (panel, eyebrow, heading, body, rule, well, bar, pill, nav-bar, button-primary/ghost/danger, modal/modal__sheet/modal__title/modal__close, sheet, tally, card, tier-disc, pips/pip, keycap, event, resource-strip, hover-tip, step, alert, objective, top-bar/camp-*, overlay-*). Then **read the example fragment `pages/03-overmap-hud.html`** for the idiom. Add 2–4 `<div class="mock-note" style="left:..px;top:..px">…</div>` per page that explain design intent (hidden until N is pressed). Fill every screen with PLAUSIBLE DATA — a mockup full of dashes is useless. Aim for 150–350 lines per fragment and make it look finished: every panel populated, hover/selected states shown on at least one element, one disabled state where relevant.
